# Fix Critical Logic Issues & Upgrade Real-Time KOT Workflow – The Waffle Hub BCM

Please improve and fix the KOT + Billing + Kitchen Management system for “The Waffle Hub BCM”.

The application should behave like a real fast-food production system optimized for:

* High-speed waffle production
* Real-time kitchen coordination
* Proper payment handling
* Batch preparation workflow
* Low-staff operations
* Multi-device synchronization

The app should separate:

* Payment Status
* Order Status
* Kitchen Preparation Status

These should NEVER be incorrectly linked together.

---

# ISSUE 1 — Payment Logic Bug

## Current Problem

If I send an order to kitchen without collecting payment:

* When kitchen marks order as “Completed”
* The system automatically marks it as “Paid”

This is WRONG.

Kitchen completion and payment collection are separate processes.

---

# Required Fix

Create separate statuses:

## Payment Status

* Unpaid
* Partially Paid
* Paid

## Order Status

* Pending
* Preparing
* Ready
* Completed
* Delivered
* Cancelled

Kitchen staff should ONLY control:

* Preparing
* Ready
* Completed

Kitchen staff should NEVER change:

* Payment status
* Billing status

Only counter/admin should control payments.

---

# Counter Payment Workflow

If order is completed but payment is pending:

* Counter dashboard should clearly show:

  * “Payment Pending”
  * Remaining balance
  * Unpaid warning indicator

Before final closing:

* Counter staff should collect payment

Only counter/admin can mark:

* Paid
* Partially Paid
* Credit Order

---

# Split Payment Support

Need support for:

* Cash
* UPI / QR
* Mixed payment

Example:

* ₹200 Cash
* ₹300 UPI

System should properly calculate:

* Paid amount

* Category-wise production queue

# Smart Batch Production Counter System

Kitchen staff should be able to:

* Reduce pending counts while preparing batches

Example:

* Pocket Waffle Pending = 10
* Prepared batter for 4
* Remaining pending = 6

If extra batter prepared:

* Count should become negative

Example:

* Pending = 2
* Prepared = 5
* Remaining = -3

Negative values mean:

* Extra prepared stock available

---

# Dynamic Auto Adjustment Logic

If new orders come:

* Existing negative stock should reduce first

Example:

Current:
Pocket Waffle = -3

New 2 orders:
Pocket Waffle = -1

New 5 orders:
Pocket Waffle = +4

This is VERY IMPORTANT because waffle preparation happens in batches.
